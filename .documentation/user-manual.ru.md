# Руководство пользователя

Проверено 1 ноября 2026 года. Итоги восстановления функций React и постраничной сверки, включая таблицы и формы расчётов: [отчёт](../.audit/REACT_DJANGO_PARITY_REPORT.md). Финансовая матрица сравнивается с Django-формой постоянными регрессионными тестами.

## Запуск

Настройте `.env` по `.env.example` и выполните `docker compose up -d --build` из корня проекта. Откройте адрес nginx, указанный в `compose.yaml`. Для локальной разработки используйте `.venv\Scripts\python.exe manage.py runserver` и Vite из `frontend` (`npm ci`, `npm run dev`). Рабочий интерфейс React находится по `/app/`; при отключённом `REACT_FRONTEND_LEGACY_REDIRECTS_ENABLED` доступны и Django-страницы.

После обновления Docker-сборки перезагрузите страницу браузера, чтобы получить новый интерфейс. Версия его ресурсов обновляется автоматически.

## Проверка установки

Полный backend-набор можно проверить командой `./scripts/run-backend-tests.ps1` из корня проекта при работающем Docker. Скрипт собирает приложение, запускает отдельные PostgreSQL и Django без публикации портов и удаляет свой временный стенд после проверки. Для одного файла используйте `./scripts/run-backend-tests.ps1 -TestPath api_v1/test_catalog_case_insensitivity.py`. Ошибка запуска или тестов завершает скрипт с ошибкой.

Тестовая PostgreSQL 18 использует Unicode-локаль `C.UTF-8` с провайдером `builtin`. Она нужна для поиска и проверки дубликатов русских названий без учёта регистра. При самостоятельном создании нового тестового кластера передайте `initdb` параметры `--encoding=UTF8 --locale-provider=builtin --builtin-locale=C.UTF-8`. Одна опция `--no-locale` задаёт локаль `C`, в которой регистр кириллицы не преобразуется.

## Основные разделы

Каталог содержит объекты, застройщиков, группы компаний и ЖК. Карточка объекта показывает свойства, изображения и переход к ипотечному расчёту. Справочники объектов и локаций редактируются модераторами. Банки, ипотечные программы, программы застройщиков и ключевая ставка доступны в отдельных разделах. Импорт и внешнее обновление требуют соответствующих прав.

Метро использует отдельные вкладки «Системы метро», «Линии метро» и «Метро». Система связана с каноническим населённым пунктом — центром сети; линия относится к системе и имеет цвет. Станция имеет основную линию, список всех линий и необязательный населённый пункт. Основная линия всегда включена в список; все линии станции должны принадлежать одной системе. Станция может находиться в другом населённом пункте или регионе, чем центр сети. Перенос линии с существующими станциями в другую систему запрещён. Используемую линию нельзя удалить, даже если она указана у станции только как дополнительная. В списке станций доступны фильтры системы, линии и населённого пункта. Территории старых станций отмечены как приблизительные, определённые по системе метро. Уточните населённый пункт станции вручную и снимите признак приблизительности. Новая линия создаётся без старого города. При выборе ближайшего метро в ЖК поиск охватывает все системы России, включая станции за границей населённого пункта ЖК. Те же правила доступны на резервных Django-страницах и в административном интерфейсе.

В React-разделе «Застройщики» поле «Регионы» и фильтр «Регион» используют субъекты России из Location. Поиск и подгрузка вариантов работают на сервере. Пушкин и Стрельна относятся к Санкт-Петербургу; города и посёлки нельзя назначить вместо региона работы. Список и сортировка показывают канонические регионы. Если старая связь ещё не сопоставлена, она показана с пометкой «требует уточнения» и сохраняется при редактировании других сведений. Старые ссылки с regionId продолжают работать; выбор нового региона снимает прежний фильтр. Импорт реестра ЕРЗ сопоставляет коды и названия с каноническими субъектами, добавляет отсутствующие связи и сохраняет ручные назначения. Повторный импорт не создаёт дубликатов. Неоднозначные регионы сообщаются в результате импорта; новая связь для них не назначается автоматически. Старый API с regionIds поддерживается, новый использует regionLocationIds; одновременно передавать оба списка нельзя.

Фильтр по прежнему ID региона использует таблицу соответствий `LegacyLocationMapping`. Если связь хранит только старый ID, но соответствие уже найдено, застройщик также виден в выдаче по `Location`. Сохранение через старый API оставляет регионы, заданные только через `Location`. В резервном Django-списке отображаются актуальные названия субъектов и названия связей, требующих уточнения.

### Импорт локаций России

На страницах регионов, населённых пунктов, административных районов и метро администраторы приложения (`application_administrators`) и суперпользователи видят кнопку «Обновить данные». Обычные пользователи, сотрудники с одним лишь `is_staff` и модераторы импорт запускать не могут. Модераторы сохраняют ручное редактирование справочников. Сервер проверяет права, сессию и CSRF.

В React кнопка расположена справа в одном ряду с вкладками. Итог или ошибку текущего запуска можно закрыть кнопкой «Закрыть уведомление». После перезагрузки итог скрыт. Если общий импорт ещё выполняется, кнопка остаётся недоступной до его завершения.

На любой из трёх географических вкладок «Обновить данные» запускает один фоновый импорт регионов, административных районов и всех действующих городов, посёлков, сёл и деревень из официального ГАР ФНС. Бесплатный API метаданных `https://fias.nalog.ru/WebServices/Public/GetLastDownloadFileInfo` доступен без ключа и регистрации. Версия фиксируется на весь запуск. Из ZIP по HTTPS загружаются адресные объекты и административная иерархия. Раздел 99 (Байконур вне России) исключён. Фильтры не ограничивают импорт. Первая загрузка может занять десятки минут. Кнопка недоступна во время работы, итог появляется после завершения.

Закрытие вкладки и перезагрузка страницы не прерывают общий импорт. Повторное нажатие во время работы не создаёт второе задание. После ошибки «Обновить данные» возобновляет работу с последнего полностью сохранённого региона той же версии. Ошибка контрольной суммы или неполная иерархия отклоняет текущий регион целиком. Перезапущенный обработчик продолжает незавершённое задание. После завершения кнопка запускает новую актуализацию. Повтор той же версии использует проверенный кеш и не создаёт дубли. Снятые с учёта объекты сохраняются с неактивным статусом, а ручное отключение записи сохраняется. Архивные региональные разделы без действующих объектов не создают пустые регионы.

Полный справочник населённых пунктов доступен по `/app/locations/localities`: поиск учитывает названия и алиасы, фильтры — регион, административный район, тип и активность. Одноимённые населённые пункты различаются типом, родительской территорией, регионом и идентификатором ФИАС. Пушкин загружается как город в Пушкинском районе, Стрельна — как посёлок в Петродворцовом районе Санкт-Петербурга.

В карточке ЖК блок «Территории ЖК» позволяет модераторам и администраторам уточнить населённый пункт, добавить несколько территорий и выбрать ровно одну основную. Корпус наследует основную территорию; при необходимости выберите другую из территорий этого ЖК. Нельзя удалить используемую корпусом связь без изменения его территории. При смене основной территории прежняя сохраняется с признаком «Историческая привязка» и сама по себе больше не включает ЖК в результаты поиска. Модератор может снять этот признак, если ЖК действительно занимает несколько территорий. Основная территория не может быть исторической. Явная привязка корпуса продолжает действовать, даже если соответствующая территория ЖК стала исторической.

На главной, в списках ЖК и объектов, а также при подборе объектов клиенту доступны фильтры «Регион», «Административный район», «Населённый пункт» по полному справочнику. Они учитывают вложенные территории: Санкт-Петербург включает Пушкин и Стрельну, Петродворцовый район включает Стрельну, а Пушкинский — Пушкин. Можно выбрать населённый пункт сразу, без предварительного выбора региона. Смена региона очищает район и населённый пункт, смена района — населённый пункт; также сбрасываются выбранные ЖК и корпус. Все заданные фильтры должны соответствовать одной территории. Одноимённые населённые пункты различаются по ID и не объединяются. Фильтр объектов учитывает явную территорию корпуса, иначе — основную территорию ЖК. Фильтр ЖК также учитывает действующие дополнительные территории и явные территории его корпусов. Ссылки сохраняют фильтры в URL; старые ссылки с городом преобразуются по таблице соответствий. Без фильтров главная показывает ЖК по всей России.

Переход выполняется со слоем совместимости: старые ID регионов, городов, районов, ЖК, корпусов, квартир и станций метро сохраняются; региональные ипотечные лимиты сохраняют прежние ID. Регионы работы застройщиков используют Location с сохранением старых связей для API. Первичная миграция связывает ЖК с прежним административным районом и не угадывает населённый пункт. Уточняйте его явно в карточке. В React-формах создания и редактирования ЖК поля «Регион», «Административный район» и «Населённый пункт» используют Location и полный ГАР: города, посёлки, сёла и деревни, включая Пушкин и Стрельну. Регион и район необязательны для начала поиска. Выбор населённого пункта заполняет их по административной иерархии; смена региона очищает район и населённый пункт, смена района — населённый пункт. После смены территории нужно выбрать населённый пункт перед сохранением. Корпуса, квартиры и строки доступности метро при этом не сбрасываются. Метро можно искать за пределами населённого пункта ЖК. Несогласованные территории сервер отклоняет без сохранения. Прежний район больше не обязателен: новый ЖК создаётся без записи в старых справочниках городов и районов. Для существующего ЖК с неуточнённым населённым пунктом можно сохранить другие изменения, оставив прежний административный район. При выборе точного населённого пункта он становится основной территорией; остальные территории, привязки корпусов, квартир, фотографий и метро сохраняются. Прежние справочники сохраняются для совместимости; метро переведено на канонические локации и системы. Модель отдельной муниципальной иерархии подготовлена; системы метро и несколько линий станции используются в справочниках; общероссийский импорт ГАР обновляет географию, а метро обновляется отдельным импортом.

Кеш ГАР в Compose хранится в отдельном томе `location_import_cache`, доступном web и обработчику. Локально путь задаёт `GAR_CACHE_DIRECTORY`, по умолчанию `outputs/gar-cache`. Условия открытых данных: [ФНС](https://www.nalog.gov.ru/opendata/7707329152-fias/). При обновлении не удаляйте том PostgreSQL; перед миграцией сделайте резервную копию. Миграции добавляют таблицы и связи, не удаляя прежние поля.

Поиск обновляет список по мере ввода, отдельная кнопка «Найти» не требуется. На телефоне фильтры располагаются в одну колонку.

Для обновления полного каталога регионов, населённых пунктов и административных районов используйте общий импорт ГАР. Выборочные импорты и ручные изменения по прежним адресам API записываются в `Location` и реестр соответствий. Старые числовые ID, значения фильтров и защита используемых записей сохраняются. Прежние административные ссылки на справочники ведут в редактор локаций.

Незавершённые задания прежнего общероссийского импорта закрыты с сохранением статистики и контрольных точек. Уже записанные территории доступны в справочнике. Кнопка «Обновить данные» запускает ГАР или возобновляет сохранённое задание ГАР.

Фоновый импорт ГАР обновляет Location по идентификаторам ФИАС, ГАР и кодам субъектов. Обработчик продолжает работу независимо от открытой страницы. JSON версии 1 и импорт реестра застройщиков используют канонические локации и сохранённые прежние коды и названия. Старые ссылки, форматы запросов и существующие связи сохранены.

Старые API справочников и селекторов сохраняют URL, ID, статусы, фильтры по родителям и форматы ответов. Историческая география читается и редактируется через `LegacyLocationMapping` с прежними правами управления справочниками. Старые строки синхронизируются, пока на них ссылаются другие разделы. При удалении используемой записи API возвращает HTTP 409. ID удалённой записи остаётся зарезервированным и сохраняет связь с Location. Исторические ссылки сохраняют свою территорию, а точные населённые пункты, включая Пушкин, Стрельну и Ликино, доступны в справочнике Location.

На вкладке «Метро» выберите систему метро и нажмите «Обновить данные». Центр системы должен иметь подтверждённый идентификатор ФИАС. Линии и станции загружаются вместе. Для существующих записей сохраняются ID, точные территории, все линии станции, статусы и связи с ЖК. В справочнике линий цвет показан плашкой рядом с названием, а в редакторе его можно выбрать в поле «Цвет линии». Карточка станции показывает её населённый пункт.

Фильтр `systemId` выбирает сеть. Фильтр по населённому пункту станции использует её собственную локацию. Старые фильтры `cityId` и `regionId` используют сохранённый ID города линии, а в режиме `canonicalLocations=true` применяются к центру сети через `LegacyLocationMapping`. Линии хранят прежний ID города без внешнего ключа к старому справочнику. Старый запрос импорта сопоставляет регион и город через реестр и обновляет ту же сеть, что и запрос по `systemId`. Если городу соответствуют несколько сетей, укажите систему явно. Удаление старого города, ID которого используется линиями, возвращает HTTP 409.

Бесплатные источники выбранных импортов старых справочников и метро без ключей и регистрации: [HFLabs/city](https://github.com/hflabs/city) (CSV по HTTPS, регионы и города России, CC BY-SA 4.0), [API Wikidata](https://www.wikidata.org/wiki/Wikidata:Data_access) (городские районы, линии и действующие станции регионального метро, CC0) и [API Википедии](https://ru.wikipedia.org/w/api.php) (открытые JSON-схемы метро двух столиц и каталоги станций остальных городов, CC BY-SA). Overpass больше не используется. Для старых записей сохранена атрибуция [OpenStreetMap, ODbL](https://www.openstreetmap.org/copyright).

Состав выбранных импортов старых справочников следует этим открытым источникам; полный справочник населённых пунктов использует официальный ГАР. Метро поддерживается для Москвы, Санкт-Петербурга, Казани, Екатеринбурга, Нижнего Новгорода, Новосибирска и Самары. Будущие станции и муниципальные подразделения, не являющиеся городскими районами, исключаются. Для неподдержанной системы импорт метро отклоняется без записи данных; отсутствие районов в Wikidata также даёт пустой результат. Город проверяется по стране, названию, типу и координатам. При неоднозначном соответствии импорт отклоняется.

Повторный запуск добавляет новые записи и актуализирует названия, связи и цвета линий по устойчивым идентификаторам: КЛАДР для регионов, ФИАС для городов, Wikidata для районов и ID страниц Википедии для станций. Совпадающие ручные и прежние OSM-записи привязываются к новому источнику с сохранением ID и зависимостей. Существующие коды регионов и ручной статус активности сохраняются; новые регионы получают двухзначный код КЛАДР. Исчезнувшие из источника записи не удаляются. Неоднозначные совпадения отклоняются без частичной записи. Результат показывает количество добавленных, обновлённых, неизменённых и пропущенных записей; для метро отдельно показаны линии.

Импорты выполняются последовательно для всех пользователей приложения. При недоступности API, неполном ответе или конфликте изменения текущего импорта не сохраняются; исправьте конфликт или повторите попытку позже. Кнопка блокируется на время запроса. В контейнере Gunicorn ожидает запрос до 60 секунд; загрузка ограничена 45 секундами, одна сетевая операция — 8 секундами. Временная сетевая ошибка повторяется один раз с паузой. После обновления выполните `docker compose up -d --build --wait`: миграция меняет подпись поля источника без удаления данных.

На резервных Django-страницах регионов, населённых пунктов и административных районов доступен тот же общий фоновый импорт с теми же правами. Обновите страницу, чтобы увидеть его прогресс. Для обновления метро откройте вкладку метро и выберите систему.

`docker compose up -d --build --wait` запускает также сервис `location-import-worker`, использующий ту же PostgreSQL. Отдельные Redis/Celery не нужны. Сервис автоматически обрабатывает очередь и восстанавливает задания после перезапуска. При ручном запуске приложения без Compose обработчик запускается командой `.venv\Scripts\python.exe manage.py process_location_imports`; флаг `--once` обрабатывает одно доступное задание и завершает команду. Для проверки нового интерфейса используйте `./scripts/run-react-browser-acceptance.ps1 -TestPath browser-tests/national-location-import.test.mjs`.

Для проверки в отдельной PostgreSQL и браузере выполните `./scripts/run-react-browser-acceptance.ps1 -TestPath browser-tests/location-import.test.mjs -LiveLocationImport`. Параметр `-LiveLocationImport` включает обращения к внешнему API; без него проверяются права и интерфейс импорта. Стенд использует порт `18081` и не подключается к рабочим данным.

Живой сценарий по умолчанию проверяет Санкт-Петербург. Для проверки Москвы перед запуском задайте `$env:BROWSER_TEST_LOCATION_CITY = 'Москва'`. Сбой внешнего API завершает этот сценарий с ошибкой, а не считается успешной проверкой.

Для регионального города задайте также регион: например, `$env:BROWSER_TEST_LOCATION_CITY = 'Казань'` и `$env:BROWSER_TEST_LOCATION_REGION = 'Республика Татарстан'`.

Обработчик с `--once` возвращает ненулевой код, если выполнение задания завершилось ошибкой источника или данных. Прогресс при этом сохраняется; обычный фоновый обработчик продолжает обслуживать очередь.

### Создание и редактирование квартир

В формах квартиры поля «Регион», «Административный район» и «Населённый пункт» используют полный справочник России, включая Пушкин, Стрельну, сёла и деревни. Населённый пункт можно искать без предварительного выбора региона. Эти поля фильтруют ЖК и корпуса; отдельная территория у квартиры не сохраняется. Смена региона очищает район, населённый пункт, ЖК и корпус; смена района — населённый пункт, ЖК и корпус; смена населённого пункта — ЖК и корпус. Застройщик и остальные параметры квартиры сохраняются.

Выбор корпуса заполняет его фактическую локацию: отдельную привязку корпуса либо основную территорию ЖК. Выбор одного ЖК не ограничивает корпуса его основной территорией автоматически. Если населённый пункт старого корпуса ещё не уточнён, можно сохранить другие изменения квартиры с текущим корпусом. Уточнять территорию следует в карточке ЖК. При редактировании сохраняются прежние связи, изображения, виды из окна и остальные значения, пока вы явно их не измените. ID регионов ипотечных лимитов остаются прежними.

Резервная Django-форма использует те же территории и серверную проверку принадлежности корпуса выбранным ЖК, застройщику и территории. Большие справочники доступны поиском; первоначальные варианты ограничены 50 записями плюс текущее значение. Полный ГАР не загружается в HTML.

### Клиенты и формы

Место проживания выбирается в поле «Населённый пункт проживания» из полного справочника России, включая Пушкин, Стрельну, сёла и деревни. Территория покупки задаётся полями «Регион покупки», «Административный район покупки» и «Населённый пункт покупки». Можно указать только регион или район либо сразу найти населённый пункт. Регион определяется по выбранной территории, если не указан отдельно. Названия в вариантах выбора и карточке дополнены типом, родителем и регионом, чтобы различать одноимённые населённые пункты. Смена региона очищает район и населённый пункт, смена района — населённый пункт. Кнопка «Рассчитать ипотеку» в карточке открывает подбор объектов с сохранённой территорией и контекстом клиента.

Миграция сохраняет исходные города, районы, владельцев, расчёты, связи и прежний финансовый регион клиента, включая отсутствие региона. При изменении территории покупки финансовый регион определяется по её субъекту из Location. В карточке клиента он отображается как «Регион лимита». Для прежних привязок без однозначного лимита по Location сохраняется сумма по точному старому ID региона. Сохранение других полей профиля сохраняет финансовую привязку.

Карточка показывает подтверждённые названия из единого справочника и сохранённые названия для значений, которые ещё требуют сопоставления. Остальные поля можно изменить с сохранением прежних локаций и лимитов. Для уточнения явно выберите территории в форме. Очистка нового поля сохраняется как отсутствие выбора. Профили и связанные расчёты доступны владельцу и пользователям с соответствующими правами.

Раздел клиентов доступен после входа. В карточке клиента хранятся контакты, пожелания, бюджет и связанные рыночные/траншевые расчёты. Финансовый потенциал является предварительной оценкой. Связанные расчёты можно выбрать для общего Word-отчёта или отвязать; удаление клиента не удаляет сами расчёты.

Формы используют единые размеры однострочных полей и основных кнопок, шрифты и интервалы. Заголовки разделов расположены над полями; подсказки и ошибки показаны рядом с соответствующим полем. На узком экране поля и действия перестраиваются в одну колонку. Клавиши Tab и Shift+Tab перемещают фокус между доступными элементами; активный элемент выделен контрастной рамкой в светлой и тёмной темах.

Прежние ID города проживания, города и района покупки и района ЖК доступны в старом API для чтения и записи через реестр соответствий. Точные территории ЖК и корпусов по-прежнему определяются по `Location`. Прежний финансовый регион остаётся отдельным от территории покупки. Если изначально он был пустым, сам переход справочника не назначает региональный лимит. Суммы, результаты и связи сохранённых ипотечных и траншевых расчётов сохраняются.

### Справочники территорий

Страницы «Регионы», «Населённые пункты» и «Административные районы» используют единый справочник локаций. Прежняя ссылка «Города» также открывает населённые пункты. Доступны города, посёлки, сёла и деревни России. Пушкин относится к Пушкинскому району, Стрельна — к Петродворцовому району Санкт-Петербурга. Муниципальные образования не подменяют административные районы.

Одинцово, Пушкино, Клин и другие проверенные города Московской области, а также Нижний Новгород доступны в «Населённых пунктах». Они могут подчиняться субъекту напрямую. Для районов, отсутствующих в загруженной административной иерархии ГАР, сверка использует сведения города и ID ФИАС родителя. ЖК «Мыс» находится в деревне Ликино. Прежняя привязка к Одинцовскому городскому округу сохранена в истории. Найти ЖК можно по фильтру «Ликино» или по городу Одинцово, которому деревня подчинена в ГАР.

Формы справочников локаций расположены рядом со списком на широком экране и над списком на телефоне. Значки карандаша и удаления в строке открывают редактор и подтверждение удаления.

Во вкладках «Локации» отображаются активные записи. Поиск учитывает текущее и прежние названия. Фильтры обновляют список автоматически. Нажмите заголовок столбца, чтобы отсортировать записи, и нажмите снова, чтобы изменить направление. В форме укажите название, тип и родительскую территорию для населённого пункта или района. Поиск родителя работает на сервере. Регион родителя помогает сузить варианты. Одинаковые названия допускаются в разных территориях. В одной территории название должно быть уникальным в пределах типа.

Переименование сохраняет прежнее название для поиска, идентификаторы источника и все связи. Перенос меняет административную принадлежность территории вместе с её дочерними территориями; циклы запрещены. Официальный импорт может снова актуализировать название и иерархию, сохраняя ID и связи. Ручное отключение записи сохраняется при повторном импорте. Импортированные записи и записи со связями защищены от удаления: снимите флаг «Активно», если их нужно скрыть. Удалить можно неиспользуемую ручную запись.

Просмотр открыт всем, редактирование — модераторам и администраторам, общий импорт — администраторам приложения и суперпользователям. Те же правила действуют на резервной Django-странице. Старые ссылки редактирования разрешаются через явные соответствия. Прежние справочники и финансовые региональные связи сохранены: создание новой территории не создаёт автоматически региональных ипотечных лимитов или регионов работы застройщика.

## Навигация

Верхняя панель, боковое меню и вкладки разделов используют единые размеры, отступы и выделение текущей страницы. Активный раздел подчёркнут и выделен фоном; на карточках и формах отмечен соответствующий родительский раздел. На телефоне основные ссылки расположены во втором ряду верхней панели и сохраняют читаемый размер текста.

Tab и Shift+Tab перемещают фокус по ссылкам. В верхней панели и вкладках стрелки влево/вправо, Home и End перемещают фокус, а Enter открывает выбранный раздел. Длинная строка вкладок прокручивается горизонтально; текущая вкладка остаётся видимой при открытии страницы, переходах Назад/Вперёд и изменении ширины окна.

На узком экране боковое меню открывается кнопкой «Открыть меню разделов». Текущий пункт виден в прокручиваемой области. Tab остаётся внутри меню, Escape и кнопка закрытия возвращают фокус к кнопке открытия. Обычный переход закрывает меню и переводит фокус в содержимое страницы. Ctrl/Cmd+клик открывает ссылку отдельно и сохраняет меню. Ссылки на клиентов и истории расчётов доступны при соответствующих правах.

## Ипотечные расчёты

В резервном Django-калькуляторе (`/mortgage/?legacy=1`) оба режима используют поля «Регион», «Административный район» и «Населённый пункт» из единого справочника `Location`. Выберите территорию, застройщика, ЖК и корпус; населённый пункт можно искать по названию, включая Пушкин и Стрельну. Выбор корпуса уточняет все три поля по его фактической территории. При смене территории зависимые ЖК, корпус и квартира сбрасываются. Номер квартиры ищется на сервере в выбранном корпусе; кнопка «Показать ещё квартиры» подгружает следующие варианты. Можно ввести данные новой квартиры вручную; сохранение требует прежних прав на каталог. Старый район не обязателен. Региональный ипотечный лимит определяется через явное соответствие региона, а не совпадение числовых ID. Открытие квартиры или образца расчёта сохраняет географию, стоимость и связи; расчёты, клиентские связи и лимиты в базе не переписываются при открытии формы.

Выберите объект, задайте стоимость, скидку/удорожание, первый взнос, дату, срок и ставку. Проценты и рубли синхронизируются с учётом последнего изменённого значения. Для рыночной ипотеки доступен льготный период; для траншевой — от одного до пяти траншей, последний получает остаток суммы. Полный график открывается кнопкой после первых 12 платежей.

Поле «Объект недвижимости» объединяет поиск и выбор: начните вводить город, ЖК, корпус или квартиру и выберите вариант мышью либо стрелками и Enter. При прокрутке списка подгружаются следующие варианты. Выбор заполняет сведения об объекте и его стоимость. История расчётов открывается кнопкой в шапке калькулятора. Эти элементы одинаково работают в рыночном и траншевом режимах.

В истории сохранённых ипотечных и траншевых расчётов, их карточках и таблице расчётов клиента показаны населённый пункт, административный район и регион квартиры. Территория корпуса имеет приоритет перед основной территорией ЖК. Например, Пушкин отображается с Пушкинским районом, а Стрельна — с Петродворцовым районом Санкт-Петербурга. Поиск учитывает названия и алиасы локаций, ЖК, корпус и номер квартиры. Фильтры «Регион», «Административный район» и «Населённый пункт» ищут варианты на сервере и применяются совместно; результаты обновляются автоматически. Смена региона очищает зависимые район и населённый пункт, смена района — населённый пункт. Прежние ссылки с фильтром города поддерживаются через таблицу соответствий. Суммы, ставки, графики, транши, привязки к клиентам и региональные ипотечные лимиты сохраняются. Эти правила действуют и на резервных Django-страницах.

Рядом с историей расчётов кнопка «Настройки» открывает окно «Модификаторы». Шаг больших сумм по умолчанию — 100 000 ₽; он применяется к стоимости объекта, первоначальному взносу и суммам траншей. Отдельный шаг небольших сумм по умолчанию — 10 000 ₽; он применяется к скидке и удорожанию в рублях. Для процентных полей доступен общий шаг 1, 0,1 или 0,01 процентного пункта (по умолчанию 0,1). Введите положительные целые шаги сумм до 1 000 000 000 ₽ и нажмите «Сохранить». Настройки общие для обоих режимов и сохраняются в этом браузере; прежние настройки больших сумм и процентов сохраняются при обновлении, а новый шаг небольших сумм получает значение 10 000 ₽. «Отмена» или Escape закрывают окно без изменений. Если сохранение в браузере недоступно, настройки действуют до перезагрузки, о чём появляется сообщение.

Справа у числовых полей всегда видны кнопки −/+. Нажатие меняет значение на один заданный шаг; при удержании мышью, касанием или клавишами Enter/Пробел начинается непрерывное изменение после короткой паузы. Повтор прекращается при отпускании, выходе указателя с кнопки, отмене касания или потере фокуса. Клавиши ↑/↓ в поле используют тот же шаг. Срок и этаж меняются на 1, площадь — на 0,01 м². Минимум площади — 0,01 м², этажа — 0; кнопки, клавиши и ручной ввод не позволяют получить отрицательное значение. Суммы остаточного транша доступны только для чтения. В блоке «Условия кредита» дата первоначального взноса и годовая ставка расположены рядом на широком экране; на узком экране поля идут друг под другом.

Банк и ипотечная программа также выбираются в полях с поиском по названию. Программы доступны после выбора банка и относятся к выбранному банку. Смена банка сбрасывает программу; «Без выбора» очищает банк, а «Ручные параметры» очищает программу. Выбор программы подставляет ставку, взнос и срок с учётом действующих условий застройщика.

Траншевый калькулятор открывается с одним остаточным траншем и заполненной датой, поэтому быстрый расчёт доступен сразу после задания финансовых параметров. При добавлении траншей заполните даты новых выдач.

В поле срока в годах учитываются полные годы, как в Django-форме. Например, ввод 12,5 года задаёт 144 месяца. Точный срок задавайте в месяцах. При вводе 25 месяцев поле лет показывает 2, а расчёт использует все 25 месяцев. То же правило действует для льготного периода.

Строки рыночного графика округляются до копеек. Платёж равен сумме процентов и погашения основного долга, итоговая переплата складывается из процентов по строкам, остаток последнего платежа равен нулю. Дата взноса проверяется вместе со сроком, чтобы дата окончания помещалась в поддерживаемый календарь.

Если калькулятор открыт по ссылке на объект, расчёт доступен после загрузки его данных. При ошибке нажмите «Повторить загрузку объекта», выберите другой объект или заполните уже доступные поля ниже.

Данные объекта заполняются сразу в общей форме обоих калькуляторов. Регион, населённый пункт и административный район выбираются из полного справочника и ограничивают поиск готовых квартир, ЖК и корпусов. Застройщик, ЖК, корпус, планировка и отделка также выбираются в единых полях с поиском и подгрузкой вариантов. Выбор готовой квартиры заполняет эти поля, номер, площадь и этаж; все реквизиты доступны для редактирования. Выбор ЖК заполняет связанную локацию и застройщика, выбор корпуса учитывает его отдельную территорию. Смена региона или населённого пункта очищает зависимые район, ЖК и корпус; смена застройщика очищает ЖК и корпус. Старый район не обязателен для ЖК с канонической территорией. Оба React-калькулятора подбирают ипотечный лимит по субъекту объекта из Location. Квартиры в Пушкине и Стрельне используют лимит Санкт-Петербурга. «Очистить поля» сбрасывает данные объекта.

Быстрый финансовый расчёт и выгрузки доступны с пустыми или частично заполненными реквизитами. Для сохранения после входа выберите готовую квартиру или заполните реквизиты объекта; для ЖК без прежнего района город и район из старых справочников не требуются. Редактирование выбранного объекта использует введённые данные и требует нового расчёта перед сохранением. Существующая квартира определяется по корпусу и номеру; создание новой доступно модератору каталога. В историях сохранённых расчётов доступны карточки, Excel/Word, новый расчёт по образцу и удаление с подтверждением.

Поиск объекта работает по всему каталогу; следующие варианты подгружаются при прокрутке списка. Выбранный объект сохраняется при поиске других вариантов. Кнопки Excel и Word возле результата выгружают актуальный рыночный или траншевый расчёт без сохранения и без входа, в том числе для введённого объекта или только финансовых параметров. Выгрузка не создаёт записи в каталоге и истории.

Денежные значения отображаются с двумя знаками после запятой, включая копейки платежей и остатков. Результаты обоих калькуляторов показывают процент/дату взноса, базовую стоимость и корректировку, точный срок в месяцах, ставку и число платежей. Рыночный результат дополнительно содержит срок/ставку льготного периода, раздельное число льготных и основных платежей и долг после льготного периода. В таблице траншей есть переплата по каждому траншу; «Остаток к выдаче» означает ещё не выданную сумму. В сохранённой карточке доступна планировка квартиры, если изображение загружено; нажмите на неё для просмотра в полном размере.

При переключении старых адресов на React объект и клиент передаются из старых `property_id`/`customer` в `propertyId`/`customerId`. Старые имена фильтров и сортировки также переводятся и сохраняют контекст выборки.

## Программы застройщиков и лимиты

Список программ застройщиков обновляется при вводе названия группы компаний, ЖК, банка или программы. Эти же параметры можно выбрать в отдельных фильтрах. Кнопка «Сбросить» находится справа от последнего фильтра «Программа» на той же строке и возвращает весь список.

При выборе объекта и банковской программы применяются активные условия застройщика: конкретный ЖК имеет приоритет над всей группой. Подставляются удорожание/скидка, взнос, срок, ставка и льготный период; при смене программы восстанавливаются базовые условия. Ставки 0% поддерживаются, в том числе в льготном периоде. При превышении регионального лимита (или федерального, если регионального нет) показаны необходимый/дополнительный взнос и комбинированная ставка; примените выбранный вариант, изменив поля формы. Это подсказка, а не автоматический запрет расчёта. Учитывается также максимальная сумма программы застройщика, если она задана.

React и резервный Django-калькулятор используют для подбора лимита субъект эффективной территории объекта из Location. Для Пушкина и Стрельны это Санкт-Петербург, для Ликино — Московская область. Лимит можно задать для субъекта, у которого есть только ID Location. Если старые записи неоднозначны и у субъекта нет активного лимита по Location, подбор по субъекту использует общий лимит программы. Старый API продолжает принимать и возвращать прежние ID регионов.

Регионы работы застройщиков и региональные ипотечные лимиты выбираются из справочника `Location` в формах React и Django. Миграция сохраняет ID связей, суммы и статусы. Для исторических лимитов с неоднозначным соответствием учитывается точный старый ID региона. Повторная загрузка одного файла реестра застройщиков сохраняет существующие связи с регионами без дубликатов.

## Текущие ограничения миграции

Результаты реализации и проверок приведены в `.audit/REACT_PARITY_IMPLEMENTATION_PLAN.md`. Все действия на React-страницах выполняются в текущем интерфейсе. Ссылки на Django-формы и прежние версии удалены из списков, карточек, форм и страниц аккаунта. Для редактирования, отмены, входа и восстановления пароля используйте соответствующие кнопки текущего интерфейса. Карта зависит от доступности картографического сервиса.

## Главная страница и карта ЖК

В блоке «Жилые комплексы по территориям» можно выбрать регион, административный район или населённый пункт. Без фильтров видны активные ЖК по всей России. Карточка показывает территорию ЖК, фото, застройщика, класс, тип и описание. Из неё можно открыть подробности ЖК, его объекты, карту и презентацию, если ссылки заданы. Показатель «Населённые пункты» в «Портфеле платформы» считает действующие населённые пункты из Location, включая сёла и деревни.

«Списком» и «На карте» переключают представление. Территория и режим сохраняются в адресе, старые ссылки с городом тоже открываются. Первые 50 ЖК загружаются сразу, остальные — кнопкой «Показать ещё ЖК». На карте видны загруженные ЖК. Координаты берутся из ссылки или определяются по названию ЖК и его территории. Если картографический сервис недоступен или координаты не найдены, карточки и прямые ссылки остаются доступны. Нажмите «Повторить загрузку карты» для новой попытки.

## Список банков

Список банков обновляется по мере ввода названия в поле «Поиск». Фильтр «Программы» позволяет выбрать банки с ипотечными программами или без них. Кнопка «Сбросить» расположена справа от этого фильтра на той же строке и возвращает весь список. На узком экране таблица прокручивается внутри карточки, а длинные названия банков переносятся на несколько строк.

## Обновление банковских данных

Раскройте «Ипотечные программы» под названием банка, чтобы увидеть программы, ставки, первоначальный взнос и опубликованный предельный срок прямо в таблице.

Администратор может открыть компактный блок «Импорт банков из JSON» на вкладке «Банки» или «Импорт ипотечных программ из JSON» на одноимённой вкладке. Выберите JSON-файл в UTF-8 размером до 1 МБ и нажмите «Импортировать». После загрузки показано количество созданных, обновлённых и оставшихся без изменений записей. Ошибка проверки отменяет загрузку выбранного раздела целиком.

Для начального наполнения используйте [срез российских банков](../data/bank-catalog-ru-2026-11.json). Загрузите один и тот же файл сначала на вкладке «Банки», затем на вкладке «Ипотечные программы». Первая загрузка добавляет банки по каноническому имени и обновляет ссылки на логотипы. Вторая обновляет справочник программ и условия предложений для существующих банков. Связи, отсутствующие в файле, сохраняются. Источники и ограничения среза приведены в поле `metadata` файла.

Формат версии 1 использует поля `version`, `banks`, `programs` и `offers`. Банк задаётся полями `name` и `logo_url`, программа — полями `name`, `condition`, `is_preferential` и необязательным `credit_limit`. Предложение ссылается на `bank` и `program` по каноническим названиям и содержит `interest_rate`, `minimum_initial_payment_percent` и `maximum_loan_term_years`. Ставка и взнос указываются в процентах, срок — в годах или `null`.

## Ключевая ставка Банка России

Линейный график всей истории ключевой ставки занимает доступную ширину страницы. Соседние точки соединены прямыми отрезками. На горизонтальной оси годы подписаны с шагом от одного года. На узком экране шаг увеличивается, чтобы подписи не перекрывались. При наведении курсора точка увеличивается и показывает дату и ставку. Отдельно выделены минимум, максимум и последняя запись. Под графиком находится таблица с сортировкой по дате, ставке и изменению в процентных пунктах.

Администратор может нажать «Обновить из ЦБ РФ». Если ставка изменилась, в таблице используется дата её вступления в силу. Если ЦБ сохранил ставку, используется дата опубликованного решения и показывается изменение 0 п.п. После обновления новые записи появляются в графике и таблице. Повторное обновление не создаёт дубликатов.

## Ипотечные программы

Список обновляется по мере ввода названия или описания в поле «Поиск». Фильтр «Тип программы» расположен слева от поиска, а на узком экране над ним. Выберите льготные или рыночные программы. Кнопка «Сбросить» расположена рядом с полем поиска и возвращает весь список. В таблице название и описание находятся в отдельных столбцах, длинные описания переносятся на следующие строки.

В редакторе программы укажите федеральный лимит и нажмите «Добавить регион», чтобы задать региональное исключение. Найдите субъект РФ в справочнике Location, введите сумму и оставьте исключение активным, чтобы его применяли калькуляторы. Если у региона из старого справочника ещё нет однозначного соответствия, редактор показывает прежнюю привязку. Её можно сохранить или уточнить выбором субъекта. Старые запросы API по `regionId` продолжают работать для регионов со старым ID.

## Загрузка, ошибки и пустые данные

Страницы и вложенные блоки используют общие состояния загрузки, ошибки и пустого результата. Пока данные загружаются, виден индикатор; настройка уменьшения движения отключает его вращение. Меню остаётся доступным. Сбой проверки входа предлагает повторить запрос и не выдаётся за выход из аккаунта.

Кнопка «Повторить» доступна с клавиатуры и повторно запрашивает данные блока вместе с его зависимостями, завершившимися ошибкой. Во время запроса кнопка заблокирована. Повторная ошибка возвращает фокус к кнопке, успешная загрузка — к заголовку восстановленного блока или начальному полю формы. Если вы уже перешли к другому элементу, фокус остаётся там. При загрузке зависимых справочников фокус возвращается к прежнему полю. Повторная загрузка списка сохраняет его адрес и фильтры.

Пустой результат отличается от ошибки и подсказывает следующее действие. Во вложенной таблице кнопка «Сбросить поиск» очищает неудачный поиск, сохраняя сортировку. Карта при сбое или отсутствии координат предлагает «Повторить загрузку карты»; список ЖК и прямые ссылки остаются доступны.

При временном сбое проверки ссылки восстановления пароля нажмите «Повторить». Такая ошибка не означает, что ссылка устарела. После успешной проверки открывается форма нового пароля без токена в адресе. Для действительно недействительной ссылки показано действие «Запросить новую ссылку».

## Диалоги и уведомления

Окна удаления и отвязки расчёта используют одинаковые заголовки, отступы и кнопки. Первым выделяется «Отмена». Tab и Shift+Tab перемещают фокус внутри окна, Escape, «Отмена» или щелчок по затемнённому фону закрывает его. Перетаскивание из содержимого на фон не закрывает окно. Во время запроса закрытие и повторное подтверждение заблокированы. После закрытия фокус возвращается к исходной кнопке; если запись удалена, он переходит к заголовку списка. Те же правила закрытия и клавиатуры применяются к просмотру изображений и мобильному меню; фотографии также переключаются стрелками.

Ошибки, подсказки и результаты операций имеют единое оформление. Ошибки объявляются немедленно, обычные сообщения — без прерывания работы; появление уведомления не переводит в него фокус. Сообщения об успешном сохранении профиля, смене пароля и обновлении ставки можно закрыть кнопкой «Закрыть уведомление»: фокус вернётся к кнопке соответствующей операции. Ошибки проверки полей показаны возле полей и не закрываются отдельно. Уведомления не исчезают по таймеру. На телефоне текст переносится, а кнопки подтверждения располагаются в столбец.

## Карточки просмотра

Карточки объекта, ЖК, клиента, банка, ипотечной программы, программы застройщика и сохранённых расчётов оформлены одинаково: заголовок страницы, панель действий под ним и разделы с едиными отступами. На телефоне кнопки занимают всю ширину, характеристики располагаются в один столбец, длинные названия переносятся. Вложенные таблицы прокручиваются внутри раздела.

Кнопки доступны через Tab и Enter. В окне удаления первым выделяется «Отмена», Tab и Shift+Tab перемещаются внутри окна. Escape или «Отмена» закрывает окно и возвращает фокус к кнопке «Удалить»; пока запрос выполняется, закрытие и повторное подтверждение заблокированы. Увеличенное изображение также можно закрыть клавишей Escape с возвратом фокуса к исходному изображению.

## Работа с таблицами

Таблицы используют единые заголовки, строки, кнопки действий, панели фильтров и пагинацию. Фильтры справочников, статуса и типа объединяют поиск и выбор в одном поле: ввод сужает варианты, Enter применяет выбранный вариант, Escape отменяет поиск. Смена фильтра или сортировки возвращает соответствующий список на первую страницу, сохраняя остальные фильтры и контекст клиента.

Широкие таблицы прокручиваются внутри своей области. Перейдите к ней клавишей Tab и используйте стрелки для прокрутки; заголовки сортировки и кнопки «Назад»/«Далее» также доступны с клавиатуры. В активном заголовке показано направление сортировки, а пагинация сообщает текущую страницу. На узких экранах счётчик страницы расположен над кнопками; карточки списков остаются доступны там, где предусмотрено мобильное представление.

Нажмите на заголовок столбца для сортировки по возрастанию, повторно — по убыванию. Стрелка показывает направление; заголовки доступны с клавиатуры. В списках с пагинацией сортируется вся серверная выборка, фильтры сохраняются, страница сбрасывается. На телефоне таблица прокручивается горизонтально внутри своей карточки; сортировка также доступна по заголовкам. Отдельного списка «Сортировка» нет.

Текстовый поиск применяется при вводе с задержкой 250 мс. В некоторых списках также доступна кнопка «Найти». Вложенные таблицы банков, лимитов, корпусов, метро, траншей и графиков имеют отдельное поле «Поиск в таблице»; сортировка и поиск работают по всем загруженным строкам. Поиск в графике охватывает весь расчёт даже при показе первых 12 платежей. Можно вводить даты в отображаемом формате и денежные значения с запятой. Широкие вложенные таблицы прокручиваются внутри карточки на телефоне.

Таблицы на всех размерах экрана не показывают технические ID, даты создания/обновления, служебные флаги активности и ключи сопоставления. Даты расчётов, платежей и записей о ключевой ставке сохранены как бизнес-данные. В расчётах клиента отдельно виден первый взнос.

Поля описания в формах рядом с таблицами используют те же шрифты, фон, рамки и выделение фокуса, что и остальные поля сайта, в светлой и тёмной темах. Высоту многострочного поля можно менять по вертикали. Пустой справочник показывает сообщение об отсутствии записей; сортировка строк становится доступна после появления данных.

## Фильтры каталога и расчётов

В каталогах ЖК и квартир показаны канонический населённый пункт, административный район и регион. Столбец «Населённый пункт» сортирует по отображаемому населённому пункту до разделения на страницы, включая города, посёлки, сёла и деревни. Фильтры региона, административного района и населённого пункта применяются совместно. ЖК находится по любой актуальной территории или явно назначенной территории корпуса; отображение и сортировка ЖК используют основную территорию. Квартира использует явную территорию корпуса, а при её отсутствии — основную территорию ЖК. Неиспользуемые исторические территории ЖК не создают совпадений.

Те же правила действуют в резервных Django-списках. Поиск учитывает названия и алиасы локаций, названия ЖК и застройщиков, номера корпусов и квартир в соответствующем каталоге. Варианты ЖК и корпусов загружаются с сервера в пределах выбранной территории. Смена географического родителя очищает зависимые значения и прежний городской фильтр. Старые городские ссылки и идентификаторы API разрешаются через таблицу соответствий. Для ЖК с привязкой на уровне района отображаются актуальные названия локаций, а старые идентификаторы сохраняются. Если у ЖК ещё нет ни одной территории, используется соответствие прежнего района. Запрос старого API со сменой района обновляет районную привязку ЖК и сохраняет её историю. Для ЖК с уже уточнённым населённым пунктом такой запрос обновляет только старый идентификатор района.

Справочные фильтры во всех табличных разделах объединяют выбор и поиск в одном поле. Варианты загружаются автоматически; откройте поле и введите часть названия. Прокрутка списка загружает следующие варианты. Пункт «Все» снимает только этот фильтр. Выбор другого города, региона или группы сбрасывает зависимые поля, если прежний выбор больше не подходит. Стрелки и Enter выбирают вариант, Escape закрывает список без изменения выбора.

Кнопка «Сбросить» всегда доступна в панели, в том числе при пустом результате: она очищает фильтры, пагинацию и сортировку. Контекст выбора объекта/расчёта клиенту сохраняется; в карточке клиента очищаются только фильтры его связанных расчётов. В каталоге объектов общего поля «Поиск по каталогу» нет — используйте отдельные поля. Поиск по названию, описанию или контактам сохранён в списках, где его не заменяют другие поля. Поиск из старой ссылки отображается отдельной подсказкой с действием «Убрать»; общий сброс также снимает его.

В каталоге объектов можно совместно выбрать город, застройщика, ЖК, корпус, планировку и задать номер квартиры, точную площадь и стоимость. В обеих историях и связанных расчётах клиента доступны город и диапазоны стоимости, взноса, платежа, срока в годах и ставки. Диапазон платежа использует основной платёж рыночной ипотеки или последний платёж траншевой. Для траншевой истории отдельно показаны максимальный и последний платежи.

Числовые фильтры применяются при вводе с задержкой 250 мс и сбрасывают страницу списка. Границы включаются в результат; денежные границы сравниваются с отображаемой точностью до копеек. Например, срок от `2.08` до `2.09` года выбирает 25 месяцев. Фильтры и сортировка сохраняются в URL, контекст выбора расчётов клиенту сохраняется. Старые адреса с диапазонами переводятся в соответствующие React-параметры.

## Большие справочники в формах

Если варианты выпадающего справочника не загрузились, из поля нажмите Tab, чтобы перейти на «Повторить загрузку справочника», затем Enter. После запуска повтора фокус возвращается в поле поиска.

Во время загрузки и при ошибке одиночное нажатие Enter сохраняет прежний выбор, включая множественные значения. Ошибка показана рядом с полем и объявляется экранным диктором. Пока повторный запрос выполняется, его нельзя запустить ещё раз. Для явной очистки переместитесь стрелкой к «Все», «Не выбрано» или «Очистить выбор» и нажмите Enter; при ошибке запроса это действие остаётся доступным.

При переходах Tab и Shift+Tab поле остаётся видимым под верхней панелью. На коротком экране высота выпадающего списка уменьшается; варианты и действия прокручиваются внутри него, в том числе касанием.

Во всех React-формах объекта, ЖК, клиента, застройщика, банка, ипотечных и девелоперских программ, региональных лимитов и локаций поиск и выбор справочника объединены в одном поле. Такой же выбор региона, района и населённого пункта доступен на главной. Начните вводить название, выберите вариант мышью или стрелками и Enter. Escape или выход из поля отменяет незавершённый поиск и сохраняет прежний выбор. Для очистки одиночного значения выберите «Не выбрано», в фильтрах — «Все». Поиск учитывает выбранного родителя; повторный выбор того же родителя сохраняет дочерние значения, а смена региона, населённого пункта, застройщика, ЖК или группы компаний очищает зависимые поля.

В полях нескольких регионов застройщика, планировок и льготных программ клиента, видов из окна объекта можно последовательно добавлять варианты через поиск, без Ctrl/Cmd. Выбранные значения показаны над полем; кнопка «Убрать» удаляет отдельное значение, пункт «Очистить выбор» снимает весь выбор. Поиск и добавление нового варианта сохраняют остальные выбранные значения. Кнопки удаления доступны с клавиатуры.

Большие справочники ищутся на сервере и подгружаются при прокрутке списка. Кнопка «Показать ещё варианты» внутри списка также доступна через Tab и Enter. Сохранённые значения загружаются отдельно, даже если их нет на первой странице. При ошибке загрузки используйте «Повторить загрузку справочника».

Подробности ролей и эксплуатации: `role_model.md`, `application_initial_setup.md`, `manual_deployment.md`.

## Каталог и фотографии жилых комплексов

В формах создания и редактирования ЖК заголовок и описание каждой секции расположены над сеткой полей, занимающей всю ширину секции. Для справочников и кварталов используется единый выпадающий список с вводом: начните печатать для фильтрации, выберите вариант мышью или стрелками и Enter. Escape отменяет поиск и возвращает выбранное значение. Дополнительные варианты больших справочников подгружаются при прокрутке списка. Обязательные поля отмечены звёздочкой, ошибки показаны под полем. Фильтр региона очищает выбор населённого пункта, чтобы можно было выбрать другой. Станции метро автоматически не удаляются. Изменения населённого пункта сохраняются одной транзакцией с полями ЖК, корпусами и фотографиями. Названия региона и населённого пункта в карточках и экспортах определяются по точной территории, а старые региональные ID ипотечных лимитов сохраняются.

На странице «Жилые комплексы» поиск применяется при вводе. Доступны фильтры застройщика, города, класса и типа недвижимости, а также сброс фильтров. Название ведёт в карточку ЖК. В основном блоке показаны станции метро и время в пути. Перед названием станции расположена полоска цвета её линии. Название линии доступно при наведении на полоску и для скринридера. Иконка пешехода означает пешую доступность, транспорта — поездку, поезда — электричку.

В нижней таблице «Доступность метро» перед станцией также показана полоска цвета линии; отдельного столбца «Линия» нет. Поиск в таблице находит как названия станций, так и линий.

При подтверждении удаления ЖК начальный фокус находится на «Отмена». Tab и Shift+Tab переключают кнопки внутри окна. Escape или «Отмена» закрывает окно и возвращает фокус на кнопку «Удалить» в карточке.

Все фотографии карточки ЖК собраны в карусели в основном блоке. Высота блока фиксирована: 400 пикселей на широком экране и 300 на узком. Снимки целиком помещаются в область без обрезки и искажения пропорций. Свободное место по краям заполняется фоном блока. Используйте кнопки «Предыдущее фото» и «Следующее фото» или стрелки клавиатуры, когда фокус находится в карусели. Нажатие на снимок открывает увеличенное изображение целиком в области постоянной высоты с тем же перелистыванием; Escape закрывает просмотр.

Модератор каталога загружает несколько изображений в блоке «Фотографии ЖК» на странице создания или редактирования ЖК. До сохранения доступны предпросмотр новых файлов и выбор «Главное фото» под новым или ранее загруженным снимком. Главное фото отображается первым в карточке и на главной странице. Фотографии и выбор главного сохраняются вместе с формой кнопкой «Создать ЖК» или «Сохранить изменения»; ошибка не оставляет частичных изменений. В галерее допускается до 30 фотографий. Повторная загрузка того же файла не создаёт ещё одну фотографию.

На странице редактирования под каждым сохранённым снимком доступна кнопка «Удалить фото». Снимок помечается на удаление; до сохранения формы его можно восстановить. При удалении главного фото главным автоматически становится следующее из оставшихся в порядке галереи, включая новые выбранные файлы. Если удалены все фотографии, в карточке показывается заглушка. Удаление применяется кнопкой «Сохранить изменения»; отмена формы не удаляет фото. При ошибке сохранения фотографии остаются в базе.

Администратору на странице каталога доступен компактный блок «Импорт жилых комплексов из JSON». Выберите UTF-8 JSON-файл размером до 16 МБ. Используйте [подготовленную подборку](../data/complexes-moscow-spb-2026-11.json). Фотографии встроены в файл, ссылки на исходные материалы указаны у каждой записи.

Импорт поддерживает версии 1 и 2. Сначала загрузите справочник локаций ГАР и нужные системы метро. Импорт ЖК не создаёт записи в старых таблицах регионов, городов и районов. Формат версии 1 сохранён: регион, region_code, city и district сопоставляются с существующей канонической географией. Неизвестные и неоднозначные территории отклоняют весь файл. Если старый файл описывает город и его административный район без точного населённого пункта, сохраняется этот уровень точности. Совместимая старая запись не заменяет уже уточнённый Пушкин или Стрельну общей территорией Петербурга.

В версии 2 вместо старых географических полей передайте location с ровно одним полем: `{"fias_id":"GUID ФИАС"}` или `{"id":123}`. Локация должна быть населённым пунктом либо федеральным городом в роли населённого пункта. GUID переносим между установками, ID относится к текущей БД. Для Пушкина используйте ФИАС `110d6ad9-0b64-47cf-a2ee-7e935228799c`, для Стрельны — `3eece910-1326-4602-aa21-e4ee117275ad`.

```json
{
  "version": 2,
  "complexes": [{
    "key": "example:pushkin",
    "name": "Пример ЖК",
    "location": {"fias_id": "110d6ad9-0b64-47cf-a2ee-7e935228799c"},
    "developer": "Название застройщика",
    "real_estate_class": "Комфорт",
    "real_estate_type": "Квартира",
    "description": "Описание ЖК",
    "buildings": [{"number": "1"}],
    "metro": [],
    "photos": [],
    "sources": ["https://example.com/project"]
  }]
}
```

Замените примерные данные проекта своими; класс должен существовать в справочнике. Список buildings содержит от 1 до 100 записей. Метро в версии 2 задаётся через station_id, station_source_identifier либо station и line вместе с system_id или system_location. Последнее поле использует ту же ссылку id/fias_id на центр сети. Для создания новой линии требуется color в формате #RRGGBB. У каждой связи укажите mode («Пешком», «На транспорте», «На электричке») и minutes от 1 до 1440. Станция может находиться вне населённого пункта ЖК; её собственная география и все линии сохраняются. Старые названия станции и линии версии 1 также поддерживаются; неоднозначная сеть требует явной ссылки в версии 2.

В версии 2 metro и photos можно не передавать или передать пустыми: существующие связи метро и галерея сохраняются. Фотография содержит name и data в base64; за один импорт допускается до 3 изображений. primary_photo задаёт индекс главного снимка с нуля и передаётся только вместе с новыми фотографиями. Версия 1 сохраняет требование хотя бы одной станции и фотографии. Источники и примечания остаются в sources, notes и metadata.

Сопоставление выполняется по устойчивому key либо нормализованному имени в конкретной территории. Для переименования можно указать match_name. При переносе существующего ЖК без ключа источника версия 2 принимает match_location с прежним id/fias_id; в версии 1 сохранён match_city. Исходные ID ЖК, корпусов, квартир, фотографий и связей метро сохраняются. Прежний district ЖК не перезаписывается. Явные территории корпусов и прежние территории ЖК остаются связаны с объектами; перенесённый ЖК не перемещает автоматически квартиры из корпуса с собственной территорией. Финансовые расчёты, клиентские связи и региональные лимиты не изменяются.

Корпуса и станции объединяются с существующими записями; отсутствующие в файле сохраняются. Повторный запуск не создаёт дубли ЖК, корпусов, станций и фотографий. Любая ошибка отменяет весь файл и удаляет только файлы, созданные неуспешной загрузкой. Кнопка снова доступна после успеха или ошибки, обновление списка не блокирует повторный импорт. Доступ к импорту остаётся у администраторов приложения и суперпользователей, с проверкой сессии и CSRF.

В подборке сроки корпусов сверены 7 ноября 2026 года. [Журнал сверки](complex-schedule-audit-2026-11-07.md) содержит прежние и уточнённые значения, основания и неразрешённые случаи; структурированные сведения находятся в metadata.schedule_verification. Дата РВЭ означает фактический ввод, срок передачи квартир остаётся плановым. Квартал сохраняется как год и квартал. Для неподтверждённых или противоречивых сроков переданы явные null: при импорте они очищают прежние значения, сохраняя корпус и связи с объектами. Поле, отсутствующее в записи корпуса, сохраняет прежнее значение. Некоторые карточки ЕИСЖС доступны только в поисковом индексе; ограничения свежести указаны в журнале.

[Дополнительная сверка от 8 ноября](complex-schedule-followup-2026-11-08.md) уточняет оставшиеся четыре записи по декларациям. Заглушки заменены конкретными корпусами: «Витебский Парк» — 3, «Галактика» — 9.3. Для переименования укажите в записи корпуса новый number и прежний match_number, например `{"number":"3","match_number":"1"}`. Импорт сохраняет ID корпуса и квартиры. Повторная загрузка находит новый номер; в пустом каталоге создаётся сразу новый номер. Если старый и новый номера принадлежат разным корпусам, соответствие неоднозначно или в существующем ЖК не найден ни один из номеров, импорт отклоняется без частичного обновления. Поле match_number не создаёт отдельный справочник алиасов.

Дальнейший переход локаций выполняется в React. Резервные Django-формы не развиваются; их удаление запланировано после завершения миграции и ручной проверки React-форм. Старый формат API и JSON-импорта ЖК пока поддерживается.
