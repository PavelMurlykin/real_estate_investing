# Переход справочников локаций — 16 ноября 2026

## Реализованные этапы

1. Аддитивные миграции `location.0009`, `property.0016–0017` добавляют
   типизированные территории, внешние идентификаторы, алиасы, административное
   дерево с индексом предков и соответствия старым ID. Федеральный город имеет
   одну территорию для региональной и городской роли. Отдельно подготовлены
   муниципальная иерархия, системы метро и несколько линий станции.
2. Миграция сохраняет исходные таблицы и внешние ключи. ЖК получает основную
   территорию прежнего района, без догадок о населённом пункте. Корпуса наследуют
   её, пока явно не выбрана другая территория этого ЖК. Старые станции метро,
   доступность метро, квартиры и финансовые региональные привязки сохраняются.
3. Общероссийский импорт использует бесплатный официальный API версий ГАР ФНС
   и ZIP HTTP Range. Проверяются диапазоны, CRC, размер и полнота иерархии.
   Версия закрепляется за заданием; регион и его прогресс записываются атомарно.
   Исторические пустые разделы не создают регионы, раздел 99 исключён.
   GUID сохраняет идентичность при переименовании. Совпадающие названия деревень
   в разных районах не объединяются. Исчезнувшие объекты сохраняются неактивными.
4. React `/app/locations/localities` показывает полный справочник. В карточке ЖК
   доступно несколько территорий, одна основная и уточнение для корпуса.
   Фильтр ЖК включает вложенные территории. Импорт разрешён только группе
   `application_administrators` и суперпользователям; изменение территорий также
   доступно модераторам. Сохраняются session authentication и CSRF.

Снимок ГАР **20261113**: 95 разделов, 89 действующих регионов,
160 303 населённых пункта уровней 5–6 и 1940 административных районов источника.
Дополнительно сохраняются прежние записи, которые требуют сверки, и проверенные
районы Петербурга. Шесть архивных разделов пустые: 80, 81, 82, 84, 85, 88.

[перечне администрации Санкт-Петербурга](https://www.gov.spb.ru/gov/otrasl/trud/socialnye-voprosy/siroti/perechen-vnutrigorodskih-municipalnyh-obrazovanij/).

Регрессионные проверки: 130 backend-тестов на отдельной PostgreSQL,

проверили поиск, административные связи, изменение территории ЖК, сохранность
прежних связей, права и экран 360 px. Дополнительно рабочая страница проверена

приложении и проверены отдельно.

## Второй этап: формы ЖК по населённому пункту

Миграция `property.0018` снимает обязательность прежнего `district`, не изменяя
его существующие значения. React и резервная Django-форма принимают населённый
пункт из полного ГАР. Новые ЖК создаются без фиктивных записей в прежних таблицах
City/District. Для неуточнённых старых ЖК сохраняется возможность изменить другие
поля, не угадывая населённый пункт.

Выбор населённого пункта атомарно обновляет основную территорию; прежние связи
остаются вторичными, а заданные территории корпусов сохраняются. Карточки квартир
и экспорты учитывают территорию корпуса и её наследование. Станции метро не
удаляются автоматически. Региональные финансовые идентификаторы сохраняются через
таблицу соответствий. Ответы API допускают отсутствие прежних cityId/districtId;
чтение старых ЖК и прежние клиенты с districtId продолжают работать.

Перед обновлением создана резервная копия
`outputs/backups/before-locality-forms-20261116.dump`. Сверены хеши всех исходных
полей 19 моделей: **1 142 160 строк**, включая ГАР, иерархию и связи ЖК. После
миграции контрольные хеши совпали. Резервные копии и контрольные файлы не входят
в Git.

Проверены создание в Пушкине и изменение на Стрельну без прежнего района,
сохранение ID корпуса, прежних районов, квартир, метро и явных территорий корпусов,
одноимённые деревни, отсутствие фиктивных городов/районов, ручной калькулятор и
резервная форма. Справочники в React загружаются поиском и страницами; резервная
форма не выгружает весь ГАР в HTML. Списки загружают географию пакетно после
пагинации. Руководства RU/EN актуализированы.

Проверки второго этапа: полный backend-набор — 782 теста и 4 subtests;
последующие затронутые сценарии — 69 тестов; React — 384 теста;
TypeScript, ESLint и production build — успешно. Восемь браузерных сценариев
прошли на 360/1280/1440 px, включая создание квартиры в ЖК без прежнего района.

## Оставшийся слой совместимости

Старые таблицы и региональные финансовые связи сохраняются. Удаление старых
таблиц и перевод оставшихся исторических фильтров на канонические ID выполняются
отдельно после сверки записей `needs_review`. Муниципальные образования не
подменяют административные районы. Метро обновляется отдельным импортом.
Возврат к старому ограничению NOT NULL после создания ЖК без района потребует
разбора таких записей; нельзя автоматически назначать фиктивный район.
