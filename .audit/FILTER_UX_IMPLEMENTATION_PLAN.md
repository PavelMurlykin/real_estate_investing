# Исправление интерфейса фильтров

Основание: замечания пользователя к `/app/properties/` от 01.11.2026. Рабочая ветка `feature/108-frontend`, работающий Docker на `localhost:18080`.

## Требования

- Справочные фильтры автоматически загружают варианты; отдельные кнопки загрузки не нужны.
- Один поисковый комбобокс на справочный фильтр, пункт «Все» сбрасывает этот фильтр с учётом каскадов.
- Удалить дублирующий общий поиск объектов и отдельные списки сортировки. Сохранить сортировку по заголовкам на всех ширинах.
- Постоянно доступная кнопка «Сбросить» очищает фильтры, сохраняя контекст клиента/родительской страницы.
- Проверить все списки/вкладки, каскады, URL, большие справочники, клавиатуру, мобильный интерфейс. Рабочие данные не менять.

## Этапы

| Этап | Содержание | Статус |
|---|---|---|
| 1 | Общий комбобокс для фильтров, автоматическая загрузка и догрузка, индивидуальное «Все» | Реализован и проверен; готов к commit/push |
| 2 | Все панели фильтров, удаление дублирующих элементов, общий сброс, таблицы на мобильных устройствах | Ожидает |
| 3 | Тесты, Docker-сборка, браузерная проверка, RU/EN руководства и отчёт | Ожидает |

Формы редактирования сохраняют обязательность выбора и серверную валидацию; пункт «Все» относится к фильтрам. Там, где отдельные поля не заменяют текстовый поиск (имя клиента, название/описание справочника и т. п.), поиск сохраняется.

На узких экранах списки будут показаны таблицами с внутренней горизонтальной прокруткой: это сохраняет сортировку по заголовкам после удаления списка «Сортировка».
