# Исправление интерфейса фильтров

Основание: замечания пользователя к `/app/properties/` от 01.11.2026. Рабочая ветка `feature/108-frontend`, работающий Docker на `localhost:18080`.

## Требования

- Справочные фильтры автоматически загружают варианты; отдельные кнопки загрузки не нужны.
- Один поисковый комбобокс на справочный фильтр; пункт «Все» снимает только его. Выбор другого непустого родителя сбрасывает зависимые значения.
- Удалить дублирующий общий поиск объектов и отдельные списки сортировки. Сохранить сортировку по заголовкам на всех ширинах.
- Постоянно доступная кнопка «Сбросить» очищает фильтры, сохраняя контекст клиента/родительской страницы.
- Проверить все списки/вкладки, каскады, URL, большие справочники, клавиатуру, мобильный интерфейс. Рабочие данные не менять.

## Этапы

| Этап | Содержание | Статус |
|---|---|---|
| 1 | Общий комбобокс для фильтров, автоматическая загрузка и догрузка, индивидуальное «Все» | Завершён: `fa20031`, push выполнен |
| 2 | Все панели фильтров, удаление дублирующих элементов, общий сброс, таблицы на мобильных устройствах | Завершён: `e3450bc`, push выполнен |
| 3 | Тесты, Docker-сборка, браузерная проверка, RU/EN руководства и отчёт | Завершён: `08c6b02`, push выполнен |

Формы редактирования сохраняют обязательность выбора и серверную валидацию; пункт «Все» относится к фильтрам. Там, где отдельные поля не заменяют текстовый поиск (имя клиента, название/описание справочника и т. п.), поиск сохраняется.

На узких экранах списки показаны таблицами с внутренней горизонтальной прокруткой: это сохраняет сортировку по заголовкам после удаления списка «Сортировка».

## Проверки

- Этап 1: общий `SearchableSelect` и вариант `RemoteSelect filter` автоматически загружают справочники, совмещают ввод/выбор, догружают при прокрутке и имеют пункт «Все». Подключены фильтры объектов и города расчёта. Общий сброс сохраняет `customerId`, для вложенного списка очищает только его префикс. Руководства RU/EN обновлены.
- 5 новых компонентных проверок — passed: автоматическая загрузка, поиск, догрузка, мышь/клавиатура/Escape/Tab, сохранение отображаемого выбора, общий/вложенный сброс. TypeScript и ESLint — passed. Остальные панели и мобильное представление относятся к этапу 2.
- Этап 2: справочные фильтры всех табличных разделов используют единый комбобокс; убраны списки сортировки и общий поиск объектов, постоянно доступен сброс. На телефоне видны сортируемые заголовки с внутренней прокруткой таблицы. «Все» снимает только один отбор; другой непустой родитель сбрасывает зависимые поля. Старый общий поиск из URL сохраняет действие и явно показан как снимаемая подсказка. Руководства RU/EN актуализированы.
- Устранён реальный переходный дефект справочников: при смене поискового запроса варианты временно откатывались к первой выборке. Данные сохраняются на время поиска в прежнем контексте; при смене родителя старые варианты не предлагаются. Проверены Enter по текущему/найденному варианту, Escape/Tab, задержанный ответ и догрузка.
- Проверки этапа 2: полный React-набор — 218 passed; TypeScript, ESLint и production build — passed; полный изолированный браузерный набор — 86 passed. На работающем приложении — 22 страницы × 2 ширины, 48 состояний справочных фильтров, 376 направлений сортировки, сброс во всех панелях. Ошибок JS/HTTP, горизонтального переполнения страницы и изменяющих API-запросов при рабочем обходе нет. Снимки панелей объектов просмотрены.
